# SOE Audit - 2026-09-30

SOE means Standardization of Engine: one shared NamEngine core that can support many verticals, while each vertical keeps its own visual identity.

The product analogy is simple: every great car starts with a great engine, but each one can still look and feel like itself.

## Scope

This audit covers the active public verticals:

- Baby
- Pet
- Business
- Boat

Product and Character are registered in code but are not part of this active SOE pass. Current contract checks show missing visual assets for those future verticals, so they should either be completed or explicitly treated as inactive before release checks include them.

## Recommended Staging Plan

1. Add release/build visibility to About and Mission Control.
2. Add a Boat Generation QA fixture so all active verticals are covered by fast QA.
3. Define active versus future verticals explicitly so Product/Character do not fail release checks until they are launch-ready.
4. Convert hard-coded review-flow slug checks into vertical configuration.
5. Standardize the intake -> review -> progress -> results handoff and keep sensitive intake details out of long URLs.
6. Standardize graphical slots:
   - name generation graphic
   - result identity graphic
   - chosen artifact graphic
   - social/share image
7. Migrate one vertical at a time in staging, preserving the current user-facing layout unless a UI change is explicitly approved.

## Release Readiness Rule

A vertical is SOE-ready only when a full first-list path passes:

- intake renders
- review behavior matches its configuration
- generation shows the progress experience
- results preserve direction data
- Mission Control records the generation
- save/share works
- paywall triggers correctly
- chosen artifact path renders or is explicitly disabled
- Generation QA has a fixture
